## 1. 테이블 구조 (v2 3-1 대체 부분)

```
departments  ✏️  id PK, name TEXT NOT NULL UNIQUE, active INT DEFAULT 1
                 🗑️ corporationId, UNIQUE(corporationId, name)
                 초기값 (10개): 경영, 경영전략기획실, 식품사업부, 전략SCM사업부, CIST&GIST,
                        기술연구소, 제주바이오센터, 음성LH센터, 생산공정센터, 두래USA
                        — CIST·GIST는 CIST&GIST로 병합(5장 1번), 중국상해법인은 대상 아님(5장 3번)

members  ✏️      id INTEGER PK (유일한 식별 키. FK 대상, 인사 연동 기준)
                 🗑️ employeeNo
                 name TEXT NOT NULL (UNIQUE 아님 — 동명이인이 생길 수 있으므로 DB는 막지 않음)
                 departmentId FK, 🆕 part TEXT NULL (파트), position (직위),
                 email TEXT UNIQUE NULL,
                 🆕 loginId TEXT UNIQUE NULL COLLATE NOCASE,
                 permission TEXT NULL CHECK(admin,manager,viewer),
                 status CHECK(재직,퇴직), passwordHash
                 🆕 CHECK(loginId IS NULL OR permission IS NOT NULL)
                 🗑️ "소속 법인은 부서에서 파생"
```

- 자산 테이블은 바뀌지 않는다. `assets.corporationId`(소유 법인, 필수)와 `assets.departmentId`(사용 부서, 선택)는 서로 독립이다. 같은 부서 자산의 법인이 섞여 있어도 된다.
- 자산번호 `{법인코드}-{유형코드}-{4자리}`도 그대로다. 법인은 자산 기준이므로 영향이 없다.
- 법인·유형 마스터와 초기값(DR/TC/SL, NB/PC/MN/PH/TV/PR/ET)도 그대로다.
- 💬 **마이그레이션**: 새 스키마는 아직 어떤 운영 DB에도 적용되지 않았다. 그래서 별도 마이그레이션을 추가하지 않고 첫 버전 스키마 자체를 고친다.

## 2. 로그인 (v2 3-5 대체 부분)

- 로그인 화면 입력 칸: "사번" → **"아이디"**
- 로그인 조건 4가지: `loginId` 일치(대소문자 무시) + permission이 NULL 아님 + passwordHash 있음 + 재직
- `loginId`는 admin만 지정한다. 권한을 부여하는 화면(구성원 수정 모달)에서 권한과 함께 입력한다.
  - 💬 형식: 영문·숫자·`.` `_` `-`, 2~30자. 한글 아이디는 받지 않는다(입력 오타·자판 전환 문제).
  - 권한을 회수하면 `loginId`와 비밀번호를 함께 지운다. 다시 부여할 때 아이디와 임시 비밀번호를 새로 정한다.
- 💬 **기존 admin 계정**: 이름 `시스템관리자`, `loginId = admin`인 시스템 계정으로 둔다. 실제 담당자 계정은 별도로 만들어 권한을 준다.
- 💬 **인사 연동 대비**: 지금은 아무것도 만들지 않는다. 연동할 때 인사 쪽 키를 담을 칸을 그때 추가해 내부 id와 연결한다. `permission`·`loginId`·`passwordHash`는 AssetHub만 관리하는 칸이며 연동 시 덮어쓰지 않는다.
- 💬 bootstrap 응답의 `loginId`는 admin에게만 내려준다(다른 사람의 로그인 아이디 목록을 노출하지 않기 위해).

## 3. 엑셀 가져오기 (v2 3-4 대체 부분)

### 3-1. 사용자 이름 찾기 규칙 🆕 (자산·구성원 가져오기 공통)

| 입력 | 찾는 방법 | 결과 |
|---|---|---|
| `홍길동` | 이름이 같은 구성원 | 1명이면 그 사람. 0명이면 "없는 구성원". **2명 이상이면 오류**: "같은 이름이 N명입니다. `이름/부서` 형식으로 적어 주세요" |
| `홍길동/기술연구소` | 이름 + 현재 부서 | 1명이면 그 사람. 0명이나 2명 이상이면 오류 |

- 앞뒤 공백은 지운다. `/` 앞뒤 공백도 무시한다.
- 💬 이름에 `/`가 들어간 구성원은 등록할 수 없게 한다(구분자와 겹침).
- 💬 같은 부서 안의 동명이인은 엑셀로 구분할 수 없다. 현재는 동명이인이 없으므로, 생기면 화면에서 직접 지정하게 한다.

### 3-2. 자산 가져오기

**자산 양식 컬럼** (✏️ = v2.1 변경)

`자산번호, 구자산번호, 법인코드*, 유형코드*, 자산명, 모델명, 시리얼, 제조년월, CPU, RAM, 저장장치, OS, 취득일자, 취득금액, 구입처, 구매품의번호, 보증만료일, 부서, 위치, 상태*, 사용자(이름)✏️, 지급일, 비고`

- 사용자: 위 이름 찾기 규칙을 쓰며, **재직 구성원 중에서만** 찾는다(퇴직자에게는 배정할 수 없으므로). 그래서 퇴직자와 이름이 같은 재직자는 이름만으로 지정할 수 있다.
- ✏️ 부서: 부서명만 받는다. 🗑️ "법인코드 | 부서명" 형식은 없앤다. 부서와 법인은 따로 검증한다.
- 코드표 시트의 부서 목록: 부서명만 표시한다.
- (참고) v2 9장 결정에 따라 이력일자 칸은 이미 삭제되었다.

### 3-3. 구성원 가져오기

**구성원 양식** ✏️: `이름*, 부서*, 파트, 직위, 이메일, 재직상태`

- 🗑️ 사번, 법인코드
- **기존 구성원 찾기** ✏️: 사번 대신 이름으로 찾는다. 이름 찾기 규칙을 쓰며, 퇴직자까지 포함한 전체 구성원 중에서 찾는다.
  - 0명이면 신규 등록
  - 1명이면 그 구성원의 부서·파트·직위·이메일·재직상태 갱신
  - 2명 이상이면 오류 (`이름/부서`로 지정)
- 💬 **주의**: 이름이 같은 **신규 입사자**를 엑셀로 넣으면 기존 사람을 갱신하는 것으로 판정된다. 미리보기 결과는 "신규 N / 갱신 N / 변경 없음 N"으로 나오므로 확인할 수 있다. 동명이인 신규 등록은 화면에서 한다.
- 💬 `이름/부서` 형식으로 기존 사람을 지정하면서 부서 칸에 다른 부서를 적으면 부서 이동으로 처리한다.
- 파일 안에서 같은 사람(같은 이름, 또는 같은 `이름/부서`)이 두 번 나오면 오류다.
- 권한·아이디·비밀번호는 양식에 넣지 않는다(v2와 같음).

## 5. 이관 데이터 (2026-10-27 결정)

원본: 대조 파일 `IT자산_대장대조_261027`(자산) + `기준정보_초안_261027`(부서·구성원·부서명 변경표).
구성원 명단에 동명이인이 없어, 설문 기기 123대 중 114대는 이름으로 사용자를 찾아 **사용중**으로 넣을 수 있다.

| # | 항목 | 결정 |
|---|---|---|
| 1 | CIST·GIST | **두 부서를 `CIST&GIST` 하나로 병합한다.** 실무에서 두 부서를 구분하지 않기 때문이다. 명단의 CIST·GIST 구성원 7명은 부서 `CIST&GIST`로 등록하고 파트는 비운다. 변경표의 구 마케팅·국내해외영업팀·전략기획팀 기기도 `CIST&GIST`로 넣는다 |
| 2 | `경영지원사업부` | 본사 대장 기기만 경영전략기획실로 바꾼다. 지사(음성LH센터) 기기는 그대로 둔다. 음성LH센터의 `경영지원사업부`는 파트 이름이다 |
| 3 | 중국상해법인 | **자산관리 대상 아님.** 부서·구성원 5명 모두 등록하지 않는다 |
| 4 | 구자산번호 `CN-`, `CO-`의 소유 법인 | 셀럭스(SL) |
| 5 | 파트 `생산PART` | `생산파트`로 통일 |

- 위 1·3번 결정에 따라 초기 부서는 **10개**, 등록할 구성원은 **75명**이다(1장 초기값 참고).
- 기준정보 초안의 "구분(본사/지사)" 칸은 부서 단위 정보라 저장하지 않는다. 2번 판단은 변환 스크립트에서 부서명 기준으로 한 번만 쓴다.

## 6. 1단계 일정 영향

이미 구현한 1단계 1~5번(스키마, 보안, 서버 쓰기 API, 구성원, 자산 가져오기)을 고쳐야 한다.

| 작업 | 예상 |
|---|---|
| 스키마 수정 (사번 삭제, loginId·part 추가, 부서 단순화, 부서 12개 초기값) | 0.25일 |
| 로그인·권한 부여 (loginId 지정·회수) | 0.25일 |
| 이름 찾기 규칙 + 구성원·자산 가져오기 수정 | 0.5일 |
| 화면 (로그인, 구성원, 기준정보, 양식 2종) + 테스트 수정 | 0.5일 |
| **추가 합계** | **약 1.5일** |

- 남은 6번(복사본으로 생애주기 검증 + smoke, 0.5일)을 포함해 **약 2일 남음. 11/10 일정에는 영향 없다.**
- 오히려 사번이 필요 없어져서 이관 데이터 준비는 쉬워졌다. 구성원 명단을 사번 없이 바로 만들 수 있다.
